# 《山海拾遗录》游戏设计文档

> 副标题：Shanhai · Echoes of the Lost Realms
> 类型：肉鸽（Roguelike）+ 卡牌构筑（Deckbuilder）+ 轻叙事 RPG
> 引擎：Godot 4.x（GDScript）
> 平台：PC 优先（Windows/Linux/macOS），后续可移植移动端
> 单局时长：30–50 分钟
> 主题词：文化传承 · 唤醒而非毁灭 · 游戏关照现实

---

## 一、立意与价值观

### 1.1 一句话立意
> 在被"忘川之雾"侵蚀的山海回响之地，少年用古籍中的记载逐一**唤醒**沦为暴戾的异兽，让被遗忘的中华文化在玩家的每一次冒险中**重新被看见**。

### 1.2 价值观锚点
| 主流价值方向 | 在游戏中的体现 |
| --- | --- |
| 文化传承创新 | 每张卡 / 每只异兽都附《山海经》原文 + 白话译注 + 考据，玩通关即"读完一部生动的山海经" |
| 游戏关照现实 | "忘川之雾 = 文化的被遗忘"。玩家"打捞文化"对应现实中文物保护、非遗传承 |
| 人与自然和谐 | 异兽不是怪物，是被扭曲的自然之灵；核心动作是"唤醒"而非"消灭" |
| 自强不息 | 死亡（败北）只是"被忘川带回"，每次重启积累 meta 进度——失败亦是积累 |
| 协作共生 | 唤醒后的异兽变为同伴卡，多元生灵协力对抗"遗忘" |

### 1.3 不做什么（红线）
- 不渲染暴力血腥（伤害用"灵韵流散"等表现）
- 不歪曲山海经原典（每条引文均注明出处篇目）
- 不出现宗教/玄学误导
- 不设氪金抽卡，单机买断

## 二、世界观与叙事

### 2.1 背景设定
祖父毕生研究山海经的少年 **方寻**，在祖父去世后整理遗物，发现一卷染着青苔的《山海残卷》。残卷上的印记将他卷入一个名为 **"山海回响"** 的镜像世界——这里栖息着山海经记载的所有生灵，但被名为 **"忘川之雾"** 的力量侵蚀，正逐一变得暴戾、扭曲、失去本性。

方寻发现：**忘川之雾的本质，是"被遗忘"**。当现实世界中再无人讲述某个神话、再无人识得某种神兽，它就在山海回响里凋零、变质。

他要做的，是用祖父留下的残卷一页页找回它们的本来面目，**唤醒**它们，让山海回响重归清明。

### 2.2 主要角色（首发可玩 3 名）
| 角色 | 流派 | 故事母题 | 设计灵感 |
| --- | --- | --- | --- |
| 方寻（学子） | 通用 / 知识 | 一个普通的好奇心驱动者 | 致敬所有为传统文化驻足的现代年轻人 |
| 阿离（九尾狐裔） | 海经 / 速度 | "我曾是被你们怕的那只" | 重塑刻板印象——温润智慧的九尾形象 |
| 燧（精卫族裔） | 山经 / 坚守 | 衔木填海，明知不可为而为之 | 致敬不放弃的精神，呼应"自强不息" |

### 2.3 五大区域（章节）
按《山海经》五经命名，对应五行：

| 区域 | 篇目对应 | 五行 | 主题情绪 | 主要异兽采样 |
| --- | --- | --- | --- | --- |
| 南山 · 朱雀庭 | 《南山经》 | 火 | 炽烈、新生 | 凤凰、毕方、鹿蜀 |
| 西山 · 白虎墟 | 《西山经》 | 金 | 肃杀、断舍 | 穷奇、陆吾、文鳐鱼 |
| 北山 · 玄武渊 | 《北山经》 | 水 | 沉静、记忆 | 烛龙、何罗鱼、肥遗 |
| 东山 · 青龙原 | 《东山经》 | 木 | 生发、希望 | 当康、犰狳、应龙幼体 |
| 中山 · 麒麟台 | 《中山经》 | 土 | 圆融、归一 | 麒麟、夔、计蒙 |

最终关 **"忘川之心"**：玩家面对的不是 BOSS，而是"被遗忘"本身。结局通过玩家**积累的图鉴完整度 + 关键事件选择**决定。

## 三、核心玩法

### 3.1 玩法循环
```
[局内 · 一次冒险]
开始 → 选择起手卡组 → 进入区域地图（节点选择）
   → 战斗/精英/事件/商人/休整 → 章节 BOSS
   → 进入下一区域 → ... → 终局 BOSS

[局外 · 长线进度]
失败/通关 → 结算典籍碎片 → 在"祖父书房"解锁
   → 新卡 / 新角色 / 新事件 / 图鉴完善
   → 开新局
```

### 3.2 战斗系统（卡牌 Deckbuilder）

**回合制 1v1~1v3**，每回合：
1. 战斗开始起手抽 4 张牌；第 2 回合起每回合开始追加摸 2 张
2. 用 **3 点"灵韵"** 出牌（可被卡牌效果增减）
3. 回合结束保留未使用手牌；打出的牌进入弃牌堆 / 消耗堆，抽牌堆不足时弃牌堆洗回

#### 三大流派
| 流派 | 资源关键词 | 主要机制 | 代表卡 |
| --- | --- | --- | --- |
| **山经 · 守拙流** | 护盾、根脉、持续治疗 | 立木为盾、扶桑回春 | 《建木》：本回合每出一张山经卡，获得 3 护盾；《扶桑朝露》：回合开始恢复 4 生命 |
| **海经 · 灵动流** | 抽卡、连击、状态 | 借浪节奏、附加"湿润/眩目" | 《应龙·呼云》：抽 2 张牌；《文鳐夜遁》：本回合下一张海经卡费用-1 |
| **荒经 · 锐意流** | 爆发、风险换收益 | 用生命换灵韵，叠加"灼焰"诅咒 | 《饕餮一咽》：弃 2 张，造成 18 伤害；《九婴回响》：失去 4 生命，下一张卡触发两次 |

> 玩家可混搭流派，但同流派"共鸣"会有额外收益（鼓励聚焦构筑）。

#### 唤醒机制（核心创新）
- 击败精英 / BOSS 时，进入 **"唤醒小游戏"**：屏幕上出现该异兽对应的山海经原文残句，玩家从 4 段白话译文里选出最贴合原文的那段。
  - 选对：异兽被唤醒，**回归本性**，作为同伴卡 / 神器卡加入卡组（永久）
  - 选错：异兽被净化但未被理解，玩家获得普通通用卡
- 这是把"读懂典籍"变成机制本身。学到的越多，越强。

### 3.3 肉鸽地图

类似《杀戮尖塔》节点图，但每个区域有专属节点类型：

| 节点 | 图标 | 内容 |
| --- | --- | --- |
| 战斗 | 普通敌群（2~4 只小兽） |
| 精英 | 1 只被忘川深度侵蚀的强敌，可唤醒 |
| 讲古驿站 | 休整，恢复生命，或用残卷研读升级一张卡 |
| 古玩铺 | 商人（神兽老者形象），用"灵韵碎片"购买卡/神器/抹除一张废卡 |
| 回响事件 | 随机民俗剧情事件（详见 3.4） |
| 山海图鉴遗页 | 拾取一张图鉴页（即使败北也保留入图鉴） |
| BOSS | 章末 BOSS，必经 |

### 3.4 回响事件（叙事+选择）

每个事件取材自真实民俗 / 山海经 / 楚辞 / 淮南子。示例：

> **事件：精卫衔木**
> 你看到一只小鸟，无声地从西山衔来枯枝，又投入海中。海始终未填，它始终未停。
> A. 上前帮她衔一段（获得卡牌 *《精卫·恒念》*：每回合首次出牌，本局永久强化 1 次。**伏笔标记：守护**）
> B. 告诉她海是填不满的（获得 30 灵韵碎片，**伏笔标记：实用**）
> C. 默默坐在她身旁，直到天亮（永久增加 5 最大生命，**伏笔标记：陪伴**）

事件累积"伏笔标记"，影响最终结局走向。

### 3.5 局外 Meta：祖父的书房

- **山海图鉴**：解锁的所有异兽/草木/神器图鉴，含原文 + 白话译注 + 现代考据 + "这一条目今天还活在哪里"（如：*"凤凰"在今天的传统纹样、戏曲、品牌LOGO中的演化*）。
- **残卷收藏**：完成的事件、达成的成就、击败的 BOSS。
- **角色解锁**：达成条件后解锁新可玩角色。
- **挑战模式**：通关后开放的高难度模式（典籍学者难度）。

## 四、积极价值的机制级落地

| 机制 | 传达的价值 |
| --- | --- |
| **击败 ≠ 消灭，而是唤醒** | 化解对立，强调理解与共生 |
| **读懂原文才能获得最强奖励** | 学习本身是奖励，反内卷 |
| **失败保留图鉴页和碎片** | 失败也有意义，鼓励坚持 |
| **多元角色与流派可混搭** | 多元共生，没有"标准答案" |
| **结局取决于积累而非操作** | 不奖励"通关玩家"，奖励"愿意理解的玩家" |
| **每条目附"今天还活在哪里"** | 把游戏关进现实——文化就在你身边 |

### 终局：化雾不灭雾

最终 BOSS"忘川之主"不是被打死的——它无法被"杀死"，因为遗忘本身不会消失。
- 真正结局触发条件：图鉴完整度 ≥ 60% 且关键事件至少做出 3 次"陪伴/守护"选择
- 终局并非战胜，而是：方寻把山海回响里看到的一切带回现实——办了一场展览 / 写了一本书 / 给孩子讲了一个故事。镜头切到现实中博物馆人来人往的一刻，一只很小的、纸做的凤凰风筝，在孩子手里飞起来。

## 五、美术与音频方向

### 5.1 美术
- **整体**：水墨工笔 + 限定色板（每个区域一套主色），UI 取古籍卷轴元素
- **卡牌正面**：异兽工笔插画（参考清代《海错图》、明代《山海经图》）
- **卡牌背面**：竖排古籍排版风
- **战斗背景**：分层视差，烟雾粒子表现"忘川"
- **参考作品**：《雾山五行》《大鱼海棠》《中国奇谭》、Cuphead 的卡通定格感（用于卡牌动效）

### 5.2 音频
- 主乐器：古琴、笛、箫、编钟，配合现代电子 pad 营造"古今对话"感
- 战斗：节奏感的中国鼓 + 电子打击
- BOSS：人声吟诵山海经原文片段（楚辞韵）

### 6.2 关键模块（GDScript 草案）

#### 卡牌资源（`Card.gd`）
```gdscript
class_name Card extends Resource

enum School { SHAN, HAI, HUANG, NEUTRAL }   # 山经/海经/荒经/通用
enum Rarity { COMMON, RARE, MYTHIC, RELIC }

@export var id: String
@export var title: String           # 中文卡名，如 "应龙·呼云"
@export var school: School
@export var rarity: Rarity
@export var cost: int = 1           # 灵韵消耗
@export_multiline var classic_quote: String   # 山海经原文
@export_multiline var translation: String     # 白话译注
@export_multiline var description: String     # 玩法描述
@export var art: Texture2D
@export var effects: Array[CardEffect] = []   # 多段效果组合
```

#### 战斗状态机
- `BattleScene` 持有 `Player`, `Enemies[]`, `Deck`（含 `draw_pile`/`hand`/`discard_pile`/`exhaust_pile`）
- 回合状态：`PLAYER_DRAW → PLAYER_ACTION → PLAYER_END → ENEMY_INTENT → ENEMY_ACT → 循环`
- 用信号驱动：`signal card_played(card, target)`，`StatusSystem`、`SchoolResonance` 都监听

#### 数据驱动
所有卡 / 敌人 / 事件 / 图鉴条目放 `data/`，不写死代码。新增内容只改数据。

## 九、为什么这款游戏值得做

1. **文化的"被读到"，本身就是一种保护**——玩家每解锁一条图鉴，相当于让一句古文被"再读一次"。
2. **机制即主题**——"唤醒"动作不是包装，它就是玩法。这让价值观不靠台词说教，而是靠手柄表达。
3. **失败也有积累**——这对当下年轻人是一种温柔的回应：不是每次都要赢，理解本身就是收获。
4. **轻量易传播**——卡牌截图天然适合社交平台分享，每张卡就是一篇山海经小科普。

## 版本路线与 MVP 范围整合

### 文档策略

GDD = 长期主设计文档，回答“游戏最终应该是什么”。
MVP-PLAN = 阶段执行索引，回答“当前阶段先做什么、不做什么、怎么验收”。

MVP-PLAN 可以整合进 GDD，但不建议让它继续承载完整设计。后续规则如下：

- GDD 是唯一长期设计事实来源，包含世界观、章节、战斗、卡牌、地图、事件、美术、UI、技术、测试和版本路线。
- MVP-PLAN 保留为轻量索引，只记录当前版本目标、范围边界和跳转到 GDD 的位置。
- 已确认的玩法和数据必须沉淀进 GDD 正文章节。
- 临时执行事项只放在 GDD 的“版本路线与 MVP 范围”或当前版本计划中，完成后归档为设计记录。
- 当 MVP-PLAN 与 GDD 冲突时，以 GDD 为准。

### 长期 GDD 扩写目标

本项目的 GDD 长期目标是在核心功能稳定后扩展到至少 200 页。扩写不是堆字数，而是按以下模块逐步补全：

- 项目概述、设计目标、目标玩家、核心循环。
- 世界观总览、章节结构、山海经原型、术语表。
- 第一章“南山 · 朱雀庭”完整设计。
- 第二章“西山 · 白虎境”完整设计。
- 后续章节预留与扩展规则。
- 角色、等级、经验、生命、能量、碎片、卡组成长。
- 卡牌系统、卡牌表、效果表、稀有度、阵营、掉落池。
- 战斗系统、敌人系统、Boss 系统、状态系统、奖励系统。
- 地图生成、顶距模式、等距模式、小地图、碰撞、设施。
- 图鉴、问答、事件、商店、驿站、宝箱、结算。
- 美术规范、动画规范、UI/UX 规范、音频规范。
- 开发者工具、调试流程、存档与重置、性能目标。
- 测试计划、版本验收标准、导出标准、风险清单。

## v0.6 开发计划：第二章「西山 · 白虎境」竖切片

### v0.6 总目标

v0.6 的核心目标是内容扩展：把一局流程从“第一章探索与战斗”扩展为“第一章 -> 第二章 -> v0.6 通关结算”。第二章必须是完整可玩的竖切片，而不是只存在地图或怪物数据。

最终玩家流程：

1. 玩家从主菜单开始新游戏，进入第一章“南山 · 朱雀庭”。
2. 玩家探索地图，打小怪、拿碎片、开宝箱、进商店、进驿站、触发事件。
3. 玩家击败第一章 3 个 Boss。
4. 游戏弹出“进入西山 · 白虎境”确认面板。
5. 玩家确认后进入第二章，保留卡组、碎片、等级、经验、最大生命，并回满当前生命和能量。
6. 玩家在第二章继续探索、战斗、构筑和成长。
7. 玩家击败第二章 3 个 Boss 后触发 v0.6 通关结算。

### v0.6 范围边界

v0.6 做：

- 第二章“西山 · 白虎境”。
- 第二章地图主题、地形颜色、障碍视觉、小地图配色。
- 第二章小怪、精英、三档 Boss。
- 第二章新卡、事件、奖励、商店权重。
- 顶距/等距双视角下的新实体识别和碰撞表现。
- 开发者跳关功能，便于未通关第一章时直接进入指定章节调试。
- R 重置确认和回到第一章开局。
- v0.6 通关结算。

v0.6 不做：

- 第三章。
- 长期章节编辑器。
- 新复杂战斗机制。
- 大规模存档系统重构。
- 大规模 UI 换皮。
- 商业版完整美术替换。

### 章节流程设计

章节状态由运行状态管理，当前规则：

- `current_chapter_index = 0` 表示第一章“南山 · 朱雀庭”。
- `current_chapter_index = 1` 表示第二章“西山 · 白虎境”。
- `bosses_defeated` 表示当前章节内已击败 Boss 数，不表示全局 Boss 数。
- 每章需要击败 3 个 Boss。
- 第一章 3 Boss 清完后不直接结算，而是弹出进入第二章确认。
- 第二章 3 Boss 清完后弹出 v0.6 通关结算。

进入第二章时：

- 保留卡组。
- 保留碎片。
- 保留等级。
- 保留经验。
- 保留最大生命。
- 当前生命回满。
- 当前能量回满。
- 当前章节 Boss 计数清零。
- 重新生成第二章地图。

R 重置时：

- 弹出确认界面。
- 确认后回到第一章开局。
- 清空当前地图状态。
- 清空本局等级和经验。
- 恢复初始最大生命、当前生命、能量、手牌和抽牌规则。
- Boss 击杀计数清零。

### 开发者跳关功能

开发者跳关是 Dev Only 功能，设计目的不是给正式玩家使用，而是为了快速验证章节、地图、美术、战斗和奖励。

当前设计：

- 地图界面右上角显示“开发跳关：关/开”。
- 默认关闭。
- 打开后显示“南山”“西山”按钮。
- 点击章节按钮后直接进入对应章节。
- 不要求通关前置章节。
- 跳关会重新生成地图。
- 跳关会清空当前章节 Boss 击杀计数。
- 跳关会回满当前生命和能量。
- 跳关保留卡组、等级、经验、碎片，便于中途构筑测试。

后续发布版本处理：

- 开发构建保留。
- 演示构建可保留但默认关闭。
- 正式发布构建建议隐藏，或挂到单独的 Debug 配置中。

## 第二章「西山 · 白虎境」设计

### 章节定位

第二章是 v0.6 的核心内容扩展。它要和第一章形成明确差异：第一章偏南山、朱雀、草地、试炼；第二章偏西山、白虎、山石、边境、守门神与异兽巡行。

设计关键词：

- 西山。
- 白虎境。
- 昆仑门庭。
- 山石、泥地、灰石障碍。
- 陆吾守门。
- 英招巡山。
- 山海异兽压迫感。

### 地图视觉规则

顶距模式：

- 第二章可走地面使用泥土地面。
- 第二章围墙/障碍保持石块视觉。
- 玩家脚下保留蓝色动态光环。
- 小怪、精英、Boss、宝箱、商店、驿站、事件节点必须可见。

等距模式：

- 第二章可走地面使用等距泥土块。
- 为避免素材透明边产生灰色裂缝，地面先绘制完整棕色菱形底，再叠泥土纹理。
- 围墙/障碍保持灰色石块，不改成草方块。
- 玩家、怪物和设施必须按脚底落点排序，避免踩到墙体贴图上层。

小地图：

- 第一章维持绿色地面和岩石障碍。
- 第二章改为棕色可走地面和灰色障碍。
- 玩家位置需要高亮。
- 当前章节 3 个 Boss 位置需要重点标记。

### 地图生成规则

第二章地图应比第一章略密，但不能牺牲可读性。

建议参数：

- 普通小怪数量：34-44 个。
- 精英数量：4 个。
- 宝箱数量：6-8 个。
- Boss 数量：3 个。
- 保留商店、驿站、事件、碎片节点。
- 保持可达性检查。
- 禁止出现“看起来能走但实际被卡”的关键路径。

第二章设施分布目标：

- 商店不能离出生点过近。
- 驿站应作为章节中段恢复点。
- 宝箱要鼓励绕路探索。
- 事件节点应分布在不同区域。
- Boss 应明显分布在不同区域，而不是聚集在同一侧。

## 第二章事件设计

第二章需要 4-6 个短事件，围绕西山、陆吾、英招、天狗、旋龟、蛊雕展开。

### 事件 1：白虎石门

- 场景：一道灰白石门横在泥地尽头。
- 选项 A：献上碎片，获得防御向卡牌。
- 选项 B：强行推门，失去生命，获得随机第二章卡。
- 选项 C：绕行，获得少量经验。

### 事件 2：英招巡山

- 场景：英招从山脊掠过，审视玩家是否有资格继续前进。
- 选项 A：接受考验，进入精英战或获得高额奖励。
- 选项 B：献上碎片，获得治疗或最大生命。
- 选项 C：避让，安全离开。

### 事件 3：天狗夜吠

- 场景：夜色中传来天狗长啸。
- 选项 A：循声追击，获得攻击卡但失去生命。
- 选项 B：静心守神，获得防御或能量相关奖励。
- 选项 C：离开，无收益无风险。

### 事件 4：旋龟伏泉

- 场景：旋龟伏在石泉旁，泉水映出玩家卡组。
- 选项 A：饮泉，恢复生命。
- 选项 B：观壳纹，获得防御卡。
- 选项 C：投入碎片，移除或强化卡牌。

### 事件 5：蛊雕裂谷

- 场景：裂谷中传来似婴儿的啼声。
- 选项 A：深入裂谷，高风险获得强力荒系卡。
- 选项 B：投石试探，获得少量碎片。
- 选项 C：离开。

### 事件 6：陆吾遗印

- 场景：石壁上刻有陆吾守门印记。
- 选项 A：触碰印记，获得 Boss 前强化。
- 选项 B：拓下纹路，获得图鉴/卡牌信息。
- 选项 C：献上碎片，获得最大生命或治疗。

## 第二章美术与表现规范

### 顶距模式实体规范

- 普通小怪使用四方向贴图。
- 精英使用更大体量，但不能遮挡格子判断。
- Boss 使用明显大于普通怪的体量，但脚底落点必须稳定。
- 宝箱、商店、驿站、事件节点都要与第二章地形风格兼容。
- 血条必须贴近实体上方，不得漂到屏幕角落。
- 经验、伤害和奖励提示必须出现在相关实体附近。

### 等距模式实体规范

- 实体排序以脚底落点为准。
- 角色和怪物不能踩到墙体贴图上层。
- 怪物不能悬空。
- 阴影应贴地，不能与脚底相距过远。
- 玩家蓝色动态光环应约等于碰撞体积。
- 第二章泥土地面不应出现灰色透明裂缝。

### 小地图规范

- 玩家标记：蓝色高亮并带外圈。
- Boss 标记：比普通怪更大，并带强调圈。
- 第一章地面：绿色。
- 第一章障碍：岩石色。
- 第二章地面：棕色。
- 第二章障碍：灰色。

### 2026-05-03：v0.6.1 启动闪退修复记录

问题现象：

- 项目启动后立即退出。
- Godot headless 普通启动报错：`res://scenes/main_menu.tscn:1 - Parse Error: Expected '['`。

原因：

- 使用 Windows PowerShell `Set-Content -Encoding utf8` 更新版本号时，`scenes/main_menu.tscn` 被写入 UTF-8 BOM。
- Godot `.tscn` 文本资源解析器在该文件第 1 行遇到 BOM 后，没有识别到期望的 `[`，导致主场景加载失败。

修复：

- 将 `project.godot`、`scenes/main_menu.tscn`、`export_presets.cfg`、`README.md`、`CHANGELOG.md` 统一重写为 UTF-8 无 BOM。
- 普通启动路径验证通过。
- v0.6.1 正式回归脚本验证通过，输出 `[v0.6 regression] PASS`。

后续规范：

- 修改 Godot `.tscn`、`.tres`、`.gd`、`.godot`、`.cfg`、`.json` 等文本资源时，不使用 PowerShell `Set-Content -Encoding utf8` 直接覆盖文件。
- 如需脚本批量写入，必须使用 `.NET UTF8Encoding(false)` 或其他明确的 UTF-8 无 BOM 写法。

### 2026-05-04：v0.6.4 地图移动与转角手感

已完成内容：

- 地图移动从单纯 X/Y 分轴尝试升级为三段式移动：
- 第一段优先尝试完整移动步长，保证开阔地移动不被拆轴削弱。
- 第二段在完整步长受阻时按输入主方向滑行，再尝试副方向，降低贴墙转弯卡住概率。
- 第三段仅在等距模式下做小幅侧向修正，用于处理视觉上贴近石块/围墙边缘时的轻微卡角。
- 碰撞半径仍沿用顶距 / 等距各自配置，不放宽 `_can_stand_at()` 阻挡判断，避免玩家穿进树墙或石墙。

设计结论：

- 本次优化目标是“减少误卡”，不是改变地图可达性。
- 角色仍不能进入阻挡格；移动手感优化只发生在合法站立点之间。
- 后续如果继续优化，应优先做碰撞体可视化调试开关，而不是再降低碰撞半径。

### 2026-05-04：v0.6.4 等距移动与所在格提示修正

问题反馈：

- 等距模式蓝色所在格有时显示到障碍物格上，容易误导玩家以为角色站在石块 / 围墙里。
- 上一版侧向微调滑步过强，表现像瞬移，贴墙时还可能出现原地抽搐。

已完成修正：

- 移除等距模式主动侧向微调，不再在玩家没有明确输入该方向时自动挤出。
- 移动逻辑改为：完整步可走则移动；完整步受阻时只尝试一个输入轴；该轴也受阻时再尝试另一个输入轴。
- 因为每帧最多只做一次轴向修正，贴墙滑行速度不会叠加，也不会出现额外弹跳。
- 等距当前格提示新增安全格回退：当前格如果是阻挡格，则使用最近安全格；如果安全格也不可用，则不绘制蓝色当前格。

设计结论：

- 等距模式的滑行只能是玩家输入方向的自然分解，不能有自动吸附或自动纠偏。
- 所在格提示必须服务于碰撞理解，绝不能画到障碍格上制造错误反馈。

### 2026-05-04：v0.6.4 等距墙体锚点修正

问题反馈：

- 顶距模式中玩家站在墙前合法可走格，但等距模式看起来像站到了石块 / 围墙贴图内部。
- 蓝色脚下光环跟随的是玩家实际位置，但石块贴图前脸向下覆盖了相邻可走格，造成“碰撞格合法、视觉格像障碍”的错觉。

已完成修正：

- 等距墙体贴图绘制锚点上移。
- 石块贴图底部现在对齐自身格子的底边，而不是继续向前压到相邻可走格中心。
- 玩家站在墙前格时，光环和脚点应落在可走地面上，不再被墙体前脸视觉覆盖。

设计结论：

- 等距障碍贴图允许有高度，但不能把“相邻可走格的主要落脚区域”画成障碍表面。
- 贴图锚点比碰撞半径更适合解决这类问题；降低碰撞半径会造成穿墙风险，不作为优先方案。

### 2026-05-05：v0.6.4 等距角色落点与提示对齐修正

问题反馈：

- 等距模式中，人物模型脚底、脚下蓝色光环和蓝色当前格提示看起来不在同一位置。
- 在贴近墙体时，顶距模式能看出玩家朝向和阻挡关系，但等距模式会误导玩家以为角色已经站到另一格。

已完成修正：

- 等距人物和实体的脚底锚点改为直接使用真实等距格中心，不再额外下移半个等距 tile。
- 等距人物脚下光环和实体阴影同步改为围绕同一个真实落点绘制。
- 碰撞和移动逻辑保持不变，只修正视觉锚点，确保“按键撞墙”与画面提示表达一致。
- 正式 v0.6 回归脚本通过，输出 `[v0.6 regression] PASS`。

设计结论：

- 等距模式中，人物脚底、阴影、光环、当前格提示和碰撞中心必须共享同一个落点定义。
- 如果玩家输入方向会撞墙，画面应清楚显示前方格是阻挡，而不是让角色模型看起来已经偏到可走格外。

- 宝箱打开结果面板新增同样的“本次变化”摘要，确保宝箱文本和实际奖励应用保持一致。
- Boss 胜利与章节最终净化面板将奖励行标注为“本次变化”，保持地图奖励节点的反馈语言一致。
- 商店购买后在商店面板保留最近一次“本次变化”摘要，明确显示购买卡牌、恢复或最大 HP 提升及碎片消耗。
- 商店库存和已售状态绑定到具体商店节点，重新进入同一商店不会刷新商品或允许重复购买已售商品。
- 驿站休整结果面板新增“本次变化”摘要，明确显示本次恢复量。
- 等距地图的视觉地面铺底外扩到真实地图边界外，避免摄像机靠近边界时露出灰底。
- 普通/精英战斗胜利返回地图后新增收益面板，显示敌人名和“本次变化”摘要。
- 普通/精英战斗、事件、宝箱、驿站、商店和 Boss 结果面板现在同时承担叙事反馈和奖励确认，不再只依赖选择预览、按钮售罄状态或地图浮字。
- `tools/v06_regression_check.gd` 新增普通/精英战斗、事件、宝箱、驿站、商店、普通 Boss 和最终 Boss 结果奖励摘要检查，确保后续奖励反馈不会退回到只有叙事文本。
- `project.godot`、主菜单页脚、README 和 CHANGELOG 同步至 v0.6.5。

设计结论：

- 事件是“叙事选择 + 资源变化”的复合节点，结果面板必须同时解释故事后果和系统收益。
- 宝箱虽然不是选择节点，也应明确展示实际收益，避免玩家错过卡牌、经验、碎片或最大生命变化。
- 普通/精英战斗是碎片和 EXP 的稳定来源，返回地图时必须给玩家一次可停留阅读的收益确认。
- Boss 奖励是章节推进节奏的关键反馈，普通胜利和最终净化面板都必须明确区分“击败 / 通关叙事”和“本次变化”。
- 商店购买是资源消耗节点，售罄按钮和碎片余额不足以说明本次收益；库存和售出状态必须属于商店节点本身，面板需要保留最近一次明确摘要。
- 驿站是节奏调节节点，也需要把环境叙事和恢复量拆开，让玩家理解补给价值。
- 等距地图边界的视觉铺底可以比真实地图更大；真实边界由墙体和碰撞定义，视觉地面负责遮住摄像机边缘的背景露出。
- 短浮字适合即时反馈，但不能成为唯一的奖励说明；玩家需要有稳定可读的确认文本。
- v0.6.5 后续切片应继续围绕事件、宝箱、商店、Boss 奖励的节奏清晰度推进。
