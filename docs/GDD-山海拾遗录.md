# 《山海拾遗录》游戏设计文档

> 副标题：Shanhai · Echoes of the Lost Realms
> 类型：肉鸽（Roguelike）+ 卡牌构筑（Deckbuilder）+ 轻叙事 RPG
> 引擎：Godot 4.x（GDScript）
> 平台：PC 优先（Windows/Linux/macOS），后续可移植移动端
> 单局时长：30–50 分钟
> 主题词：文化传承 · 唤醒而非毁灭 · 游戏关照现实

---

## 一、立意与价值观

### 1.1 一句话立意
> 在被"忘川之雾"侵蚀的山海回响之地，少年用古籍中的记载逐一**唤醒**沦为暴戾的异兽，让被遗忘的中华文化在玩家的每一次冒险中**重新被看见**。

### 1.2 价值观锚点
| 主流价值方向 | 在游戏中的体现 |
| --- | --- |
| 文化传承创新 | 每张卡 / 每只异兽都附《山海经》原文 + 白话译注 + 考据，玩通关即"读完一部生动的山海经" |
| 游戏关照现实 | "忘川之雾 = 文化的被遗忘"。玩家"打捞文化"对应现实中文物保护、非遗传承 |
| 人与自然和谐 | 异兽不是怪物，是被扭曲的自然之灵；核心动作是"唤醒"而非"消灭" |
| 自强不息 | 死亡（败北）只是"被忘川带回"，每次重启积累 meta 进度——失败亦是积累 |
| 协作共生 | 唤醒后的异兽变为同伴卡，多元生灵协力对抗"遗忘" |

### 1.3 不做什么（红线）
- 不渲染暴力血腥（伤害用"灵韵流散"等表现）
- 不歪曲山海经原典（每条引文均注明出处篇目）
- 不出现宗教/玄学误导
- 不设氪金抽卡，单机买断

## 二、世界观与叙事

### 2.1 背景设定
祖父毕生研究山海经的少年 **方寻**，在祖父去世后整理遗物，发现一卷染着青苔的《山海残卷》。残卷上的印记将他卷入一个名为 **"山海回响"** 的镜像世界——这里栖息着山海经记载的所有生灵，但被名为 **"忘川之雾"** 的力量侵蚀，正逐一变得暴戾、扭曲、失去本性。

方寻发现：**忘川之雾的本质，是"被遗忘"**。当现实世界中再无人讲述某个神话、再无人识得某种神兽，它就在山海回响里凋零、变质。

他要做的，是用祖父留下的残卷一页页找回它们的本来面目，**唤醒**它们，让山海回响重归清明。

### 2.2 主要角色（当前可玩 4 名）
| 角色 | 流派 | 故事母题 | 设计灵感 |
| --- | --- | --- | --- |
| 方寻（学子） | 通用 / 知识 | 一个普通的好奇心驱动者 | 致敬所有为传统文化驻足的现代年轻人 |
| 阿离（九尾狐裔） | 荒经 / 诡术 | "我曾是被你们怕的那只" | 重塑刻板印象，以凶势与血祭表达高风险爆发 |
| 洛泠（海经行者） | 海经 / 行雨 | 潮声带回失落的名字 | 以潮涌、湿润和手牌流动表现水势 |
| 桑岐（扶桑守望） | 山经 / 根脉 | 根脉仍在，万叶同荣 | 以护盾、根脉和生息表现稳防续航 |

### 2.3 五大区域（章节）
按《山海经》五经命名，对应五行：

| 区域 | 篇目对应 | 五行 | 主题情绪 | 主要异兽采样 |
| --- | --- | --- | --- | --- |
| 南山 · 朱雀庭 | 《南山经》 | 火 | 炽烈、新生 | 凤凰、毕方、鹿蜀 |
| 西山 · 白虎境 | 《西山经》 | 金 | 肃杀、断舍 | 穷奇、陆吾、文鳐鱼 |
| 北山 · 玄武渊 | 《北山经》 | 水 | 沉静、记忆 | 烛龙、何罗鱼、肥遗 |
| 东山 · 青龙原 | 《东山经》 | 木 | 生发、希望 | 当康、犰狳、应龙幼体 |
| 中山 · 麒麟台 | 《中山经》 | 土 | 圆融、归一 | 麒麟、夔、计蒙 |

最终关 **"忘川之心"**：玩家面对的不是 BOSS，而是"被遗忘"本身。结局通过玩家**积累的图鉴完整度 + 关键事件选择**决定。

## 三、核心玩法

### 3.1 玩法循环
```
[局内 · 一次冒险]
开始 → 读取当前角色与藏签 → 进入 96×60 区域地图（顶距 / 等距探索）
   → 普通即时战斗 / 精英与 BOSS 卡牌战斗 / 回响事件 / 古玩铺 / 驿站 / 宝箱
   → 进入下一区域 → ... → 忘川之心终局审问

[局外 · 长线进度]
失败/通关 → 结算典籍碎片 → 在"祖父书房"解锁
   → 新卡 / 新角色 / 新事件 / 图鉴完善 / 结局收藏
   → 开新局
```

### 3.2 战斗系统（卡牌 Deckbuilder）

**精英 / BOSS 使用回合制 1v1~1v3 卡牌战斗；普通小怪使用地图即时战斗。** 卡牌战斗每回合：
1. 战斗开始起手抽 4 张牌；第 2 回合起每回合开始追加摸 2 张，等级可提高后续回合灵韵和摸牌。
2. 用 **3 点"灵韵"** 出牌（可被卡牌效果增减）。
3. 回合结束保留未使用手牌；打出的牌进入弃牌堆 / 消耗堆，抽牌堆不足时弃牌堆洗回。

#### 三大流派
| 流派 | 资源关键词 | 主要机制 | 代表卡 |
| --- | --- | --- | --- |
| **山经 · 守拙流** | 根脉 / 生息 | 护盾、防御延续、恢复 | 《建木·承露》《扶桑·朝露》《根门·守息》 |
| **海经 · 灵动流** | 潮涌 / 湿润 | 抽牌、灵韵流动、湿润触发 | 《应龙·呼云》《文鳐·夜遁》《潮汐归牌》 |
| **荒经 · 锐意流** | 凶势 / 血祭 | 爆发、风险换收益、自伤代价 | 《穷奇·裂风》《饕餮·一咽》《九尾·借火》 |

> 玩家可混搭流派，但同流派"共鸣"会有额外收益（鼓励聚焦构筑）。

#### 唤醒机制（核心创新）
- 击败精英 / BOSS 时，进入 **"唤醒小游戏"**：屏幕上出现该异兽对应的山海经原文残句，玩家从多段白话译文里选出最贴合原文的那段。
  - 选对：异兽被唤醒，**回归本性**，当前版本主要作为奖励卡 / 同伴卡进入卡组。
  - 选错：异兽被净化但未被理解，玩家获得普通奖励；神器奖励属于 v1.0 完整版预留，不写成当前已实现。
- 这是把"读懂典籍"变成机制本身。学到的越多，越强。

### 3.3 肉鸽地图

当前实现不是《杀戮尖塔》式路线节点图，而是 **96×60 格连续探索地图**。玩家在顶距 / 等距双视角间切换，通过 WASD / 方向键移动，地图内随机分布实体；触碰或确认实体后进入对应交互。

| 实体 | 图标 | 当前内容 |
| --- | --- | --- |
| 普通敌人 | 敌 | 地图即时战斗，胜利给碎片、EXP 和部分图鉴解锁 |
| 精英 | 精 | 卡牌战斗，胜利后给章节化奖励，可触发唤醒奖励 |
| BOSS | 弱 / 中 / 强 | 每章三档 Boss，击败 3 个后推进章节或进入终局 |
| 古玩铺 | 市 | 用灵韵碎片购买随机卡、回血或永久最大生命 |
| 驿站 | 驿 | 章节化休整，恢复生命 |
| 宝箱 | 宝 | 抽取碎片、EXP、卡牌、回血或最大生命等奖励 |
| 回响事件 | 录 | 40 个剧情事件，选项带守护 / 陪伴 / 实用伏笔标记 |
| 图鉴 / 碎片节点 | 卷 / 光点 | 获得长期图鉴或灵韵碎片，败北后仍保留长期进度 |

### 3.4 回响事件（叙事+选择）

每个事件取材自真实民俗 / 山海经 / 楚辞 / 淮南子。示例：

> **事件：精卫衔木**
> 你看到一只小鸟，无声地从西山衔来枯枝，又投入海中。海始终未填，它始终未停。
> A. 上前帮她衔一段（获得卡牌 *《精卫·恒念》* 或同等守护向奖励。**伏笔标记：守护**）
> B. 告诉她海是填不满的（获得 30 灵韵碎片，**伏笔标记：实用**）
> C. 默默坐在她身旁，直到天亮（永久增加 5 最大生命，**伏笔标记：陪伴**）

事件累积"伏笔标记"，影响最终结局走向。v0.12 固定三类标记：

| 标记 | 显示 | 设计含义 |
| --- | --- | --- |
| `guard` | 守护 | 主动承担风险，保护被遗忘者 |
| `companion` | 陪伴 | 不急于索取收益，愿意停留和理解 |
| `practical` | 实用 | 以生存、资源和效率为先 |

标记只记录在本局 `RunState`，新局重置，不进入长期人格或角色 Meta。

### 3.5 局外 Meta：祖父的书房

- **山海图鉴**：当前解锁卡牌和异兽条目，含原文 + 白话译注 + 现代关联；草木、神器、章节和事件图鉴属于完整版扩展。
- **图鉴学习复盘**：已解锁条目打开详情后标记为已研读；图鉴提供学习总览、未研读条目复盘和终局条件解释。
- **藏签系统**：祖父书房中已实现的局外 Meta，可用典籍碎片解锁并启用起手替换规则。
- **残卷收藏 / 成就**：完成的事件、达成的成就、击败的 BOSS 属于后续扩展；当前不保存完整通关流水。
- **角色解锁**：达成条件后解锁新可玩角色。
- **终局收藏**：记录已见结局和最高结局等级，不保存完整通关流水。
- **挑战模式**：通关后开放的高难度模式（典籍学者难度）属于后置完整版；当前无正式入口。

## 四、积极价值的机制级落地

| 机制 | 传达的价值 |
| --- | --- |
| **击败 ≠ 消灭，而是唤醒** | 化解对立，强调理解与共生 |
| **读懂原文才能获得最强奖励** | 学习本身是奖励，反内卷 |
| **失败保留图鉴页和碎片** | 失败也有意义，鼓励坚持 |
| **多元角色与流派可混搭** | 多元共生，没有"标准答案" |
| **结局取决于积累而非操作** | 不奖励"通关玩家"，奖励"愿意理解的玩家" |
| **每条目附"今天还活在哪里"** | 把游戏关进现实——文化就在你身边 |

### 终局：化雾不灭雾

v0.12 终局不是最终战斗，不新增“忘川之心 Boss”。第五章「中山 · 麒麟台」最终 Boss 清完后，玩家进入独立场景 **忘川之心**，面对的是“被遗忘”本身的审问。

对话结构固定为五段：开场、三次审问、判定、结局。三次现场选择只改变即时回应文案，不改变主要结局判定；真正判定来自本局图鉴有效完成度和事件伏笔标记。

| 结局 | 条件 | 含义 |
| --- | --- | --- |
| 残响未明 | 未达以下条件 | 五境归静，但理解仍不足 |
| 五境净化 | 未达真结局，但图鉴有效完成度 ≥ 30%，或守护 + 陪伴 ≥ 1 | 玩家完成五境净化，并带回部分名字 |
| 山海重明 | 图鉴有效完成度 ≥ 60%，且守护 + 陪伴 ≥ 3 | 玩家不只通关，也积累了足够多“愿意理解”的证据 |

图鉴完成度继续使用有效 `card.* / beast.*` 口径，不读取存档里的无效 key。

## 五、美术与音频方向

### 5.1 美术
- **当前实现**：顶距 / 等距像素图集 + 章节背景图 + 卡牌框架图，优先保证小尺寸可读性和双视角一致性。
- **长期方向**：水墨工笔 + 限定色板（每个区域一套主色），UI 取古籍卷轴元素。
- **发布要求**：所有角色、敌人、Boss、设施、章节背景和终局背景必须明确“发布级 / 可接受占位 / 待替换”状态。
- **参考作品**：《雾山五行》《大鱼海棠》《中国奇谭》、Cuphead 的卡通定格感（用于卡牌动效）。

### 5.2 音频
- **当前实现**：`AudioEngine` 使用程序合成 8-bit 风格 BGM / SFX，不依赖外部音频文件；设置页可调 BGM / SFX 音量。
- **长期方向**：古琴、笛、箫、编钟配合现代电子 pad，营造“古今对话”；战斗使用中国鼓 + 电子打击。
- **发布要求**：若继续使用程序合成音频，需在公开 Demo 中作为统一风格确认；若替换外部音频，必须补授权和主题映射。

### 6.2 关键模块（GDScript 草案）

#### 卡牌资源（`Card.gd`）
```gdscript
class_name Card extends Resource

enum School { SHAN, HAI, HUANG, NEUTRAL }   # 山经/海经/荒经/通用
enum CardType { ATTACK, SKILL, POWER }
enum Rarity { COMMON, RARE, MYTHIC }

@export var id: String
@export var title: String           # 中文卡名，如 "应龙·呼云"
@export var school: School
@export var card_type: CardType
@export var rarity: Rarity
@export var cost: int = 1           # 灵韵消耗
@export var exhaust: bool = false
@export var requires_target: bool = false
@export var keywords: Array[String] = []
@export_multiline var classic_quote: String   # 山海经原文
@export_multiline var translation: String     # 白话译注
@export_multiline var description: String     # 玩法描述
@export_multiline var alive_today: String      # 今天还活在哪里
@export var effects: Array[CardEffect] = []   # 多段效果组合
```

#### 战斗状态机
- `BattleManager` 持有 `Player`, `Enemies`, `Deck`（含 `draw_pile` / `hand` / `discard_pile` / `exhaust_pile`）。
- 回合流程：玩家回合开始抽牌与同伴行动 → 玩家出牌 → 回合结束 → 敌人按意图行动 → 下一回合。
- `RunState` 保存本局 HP、灵韵、等级、经验、卡组和章节进度；`GameState` 只保存跨局 Meta。

#### 数据驱动
卡牌、敌人和事件分别由 `data/cards/cards.json`、`data/enemies/enemies.json`、`data/events/echo_events.json` 驱动。图鉴当前从卡牌与敌人数据派生，后续若扩展草木 / 神器 / 章节 / 事件图鉴，应新增独立数据源并同步统计口径。

## 九、为什么这款游戏值得做

1. **文化的"被读到"，本身就是一种保护**——玩家每解锁一条图鉴，相当于让一句古文被"再读一次"。
2. **机制即主题**——"唤醒"动作不是包装，它就是玩法。这让价值观不靠台词说教，而是靠手柄表达。
3. **失败也有积累**——这对当下年轻人是一种温柔的回应：不是每次都要赢，理解本身就是收获。
4. **轻量易传播**——卡牌截图天然适合社交平台分享，每张卡就是一篇山海经小科普。

## 历史归档：v0.6 开发计划（第二章「西山 · 白虎境」竖切片）

> 本节记录 v0.6 当时的阶段计划和验收口径，已经被 v0.14 当前事实与 GDD 补完基线覆盖。阅读当前项目状态时，应优先参考“6.3 当前原型状态”“七、内容规划（当前口径）”和“GDD v0.14 文档补完基线”。

### v0.6 总目标

v0.6 的核心目标是内容扩展：把一局流程从“第一章探索与战斗”扩展为“第一章 -> 第二章 -> v0.6 通关结算”。第二章必须是完整可玩的竖切片，而不是只存在地图或怪物数据。

最终玩家流程：

1. 玩家从主菜单开始新游戏，进入第一章“南山 · 朱雀庭”。
2. 玩家探索地图，打小怪、拿碎片、开宝箱、进商店、进驿站、触发事件。
3. 玩家击败第一章 3 个 Boss。
4. 游戏弹出“进入西山 · 白虎境”确认面板。
5. 玩家确认后进入第二章，保留卡组、碎片、等级、经验、最大生命，并回满当前生命和能量。
6. 玩家在第二章继续探索、战斗、构筑和成长。
7. 玩家击败第二章 3 个 Boss 后触发 v0.6 通关结算。

### v0.6 范围边界

v0.6 做：

- 第二章“西山 · 白虎境”。
- 第二章地图主题、地形颜色、障碍视觉、小地图配色。
- 第二章小怪、精英、三档 Boss。
- 第二章新卡、事件、奖励、商店权重。
- 顶距/等距双视角下的新实体识别和碰撞表现。
- 开发者跳关功能，便于未通关第一章时直接进入指定章节调试。
- R 重置确认和回到第一章开局。
- v0.6 通关结算。

v0.6 不做：

- 第三章。
- 长期章节编辑器。
- 新复杂战斗机制。
- 大规模存档系统重构。
- 大规模 UI 换皮。
- 商业版完整美术替换。

### 章节流程设计

章节状态由运行状态管理，当前规则：

- `current_chapter_index = 0` 表示第一章“南山 · 朱雀庭”。
- `current_chapter_index = 1` 表示第二章“西山 · 白虎境”。
- `bosses_defeated` 表示当前章节内已击败 Boss 数，不表示全局 Boss 数。
- 每章需要击败 3 个 Boss。
- 第一章 3 Boss 清完后不直接结算，而是弹出进入第二章确认。
- 第二章 3 Boss 清完后弹出 v0.6 通关结算。

进入第二章时：

- 保留卡组。
- 保留碎片。
- 保留等级。
- 保留经验。
- 保留最大生命。
- 当前生命回满。
- 当前能量回满。
- 当前章节 Boss 计数清零。
- 重新生成第二章地图。

R 重置时：

- 弹出确认界面。
- 确认后回到第一章开局。
- 清空当前地图状态。
- 清空本局等级和经验。
- 恢复初始最大生命、当前生命、能量、手牌和抽牌规则。
- Boss 击杀计数清零。

### 开发者跳关功能

开发者跳关是 Dev Only 功能，设计目的不是给正式玩家使用，而是为了快速验证章节、地图、美术、战斗和奖励。

当前设计：

- 地图界面右上角显示“开发跳关：关/开”。
- 默认关闭。
- 打开后显示“南山”“西山”按钮。
- 点击章节按钮后直接进入对应章节。
- 不要求通关前置章节。
- 跳关会重新生成地图。
- 跳关会清空当前章节 Boss 击杀计数。
- 跳关会回满当前生命和能量。
- 跳关保留卡组、等级、经验、碎片，便于中途构筑测试。

后续发布版本处理：

- 开发构建保留。
- 演示构建可保留但默认关闭。
- 正式发布构建建议隐藏，或挂到单独的 Debug 配置中。

## 第二章「西山 · 白虎境」设计

### 章节定位

第二章是 v0.6 的核心内容扩展。它要和第一章形成明确差异：第一章偏南山、朱雀、草地、试炼；第二章偏西山、白虎、山石、边境、守门神与异兽巡行。

设计关键词：

- 西山。
- 白虎境。
- 昆仑门庭。
- 山石、泥地、灰石障碍。
- 陆吾守门。
- 英招巡山。
- 山海异兽压迫感。

### 地图视觉规则

顶距模式：

- 第二章可走地面使用泥土地面。
- 第二章围墙/障碍保持石块视觉。
- 玩家脚下保留蓝色动态光环。
- 小怪、精英、Boss、宝箱、商店、驿站、事件节点必须可见。

等距模式：

- 第二章可走地面使用等距泥土块。
- 为避免素材透明边产生灰色裂缝，地面先绘制完整棕色菱形底，再叠泥土纹理。
- 围墙/障碍保持灰色石块，不改成草方块。
- 玩家、怪物和设施必须按脚底落点排序，避免踩到墙体贴图上层。

小地图：

- 第一章维持绿色地面和岩石障碍。
- 第二章改为棕色可走地面和灰色障碍。
- 玩家位置需要高亮。
- 当前章节 3 个 Boss 位置需要重点标记。

### 地图生成规则

第二章地图应比第一章略密，但不能牺牲可读性。

建议参数：

- 普通小怪数量：34-44 个。
- 精英数量：4 个。
- 宝箱数量：6-8 个。
- Boss 数量：3 个。
- 保留商店、驿站、事件、碎片节点。
- 保持可达性检查。
- 禁止出现“看起来能走但实际被卡”的关键路径。

第二章设施分布目标：

- 商店不能离出生点过近。
- 驿站应作为章节中段恢复点。
- 宝箱要鼓励绕路探索。
- 事件节点应分布在不同区域。
- Boss 应明显分布在不同区域，而不是聚集在同一侧。

## 第二章事件设计

第二章需要 4-6 个短事件，围绕西山、陆吾、英招、天狗、旋龟、蛊雕展开。

### 事件 1：白虎石门

- 场景：一道灰白石门横在泥地尽头。
- 选项 A：献上碎片，获得防御向卡牌。
- 选项 B：强行推门，失去生命，获得随机第二章卡。
- 选项 C：绕行，获得少量经验。

### 事件 2：英招巡山

- 场景：英招从山脊掠过，审视玩家是否有资格继续前进。
- 选项 A：接受考验，进入精英战或获得高额奖励。
- 选项 B：献上碎片，获得治疗或最大生命。
- 选项 C：避让，安全离开。

### 事件 3：天狗夜吠

- 场景：夜色中传来天狗长啸。
- 选项 A：循声追击，获得攻击卡但失去生命。
- 选项 B：静心守神，获得防御或能量相关奖励。
- 选项 C：离开，无收益无风险。

### 事件 4：旋龟伏泉

## 第二章美术与表现规范

### 顶距模式实体规范

- 普通小怪使用四方向贴图。
- 精英使用更大体量，但不能遮挡格子判断。
- Boss 使用明显大于普通怪的体量，但脚底落点必须稳定。
- 宝箱、商店、驿站、事件节点都要与第二章地形风格兼容。
- 血条必须贴近实体上方，不得漂到屏幕角落。
- 经验、伤害和奖励提示必须出现在相关实体附近。

### 等距模式实体规范

- 实体排序以脚底落点为准。
- 角色和怪物不能踩到墙体贴图上层。
- 怪物不能悬空。
- 阴影应贴地，不能与脚底相距过远。
- 玩家蓝色动态光环应约等于碰撞体积。
- 第二章泥土地面不应出现灰色透明裂缝。

### 小地图规范

- 玩家标记：蓝色高亮并带外圈。
- Boss 标记：比普通怪更大，并带强调圈。
- 第一章地面：绿色。
- 第一章障碍：岩石色。
- 第二章地面：棕色。
- 第二章障碍：灰色。

## GDD v0.14 文档补完基线

本节是 v0.14 的主交付：把 GDD 从“设计正文 + 执行记录混合体”推进为可执行规格书。其目标不是一次性写满 200 页，而是先给所有长期模块建立状态、规则边界、验收口径和后续开发优先级。

### 文档分层规则

- **设计正文**：从文档开头到本节结束，记录长期规则、当前事实、缺口和验收标准。
- **版本记录**：从“v0.6 开发执行记录”开始，只记录已经发生的版本事实，不再承担系统规格职责。
- **事实来源**：当前实现以 `scenes/`、`scripts/`、`data/`、`tools/` 为准；当前版本说明以 `README.md` 与 `PLAYTEST.md` 为辅，但若有冲突，以 GDD 正文为主。
- **状态标签**：
  - `已实现且已规格化`：代码已存在，GDD 已写出可执行规则和验收。
  - `已实现待规格化`：代码已存在，但 GDD 仍缺完整规则或验收。
  - `设计有缺口`：已有方向，但规则、数据或体验目标不足以直接开发。
  - `代码未实现`：GDD 有目标，当前代码没有独立系统或入口。
  - `后置完整版`：不进入外测 / 公开 Demo，放到完整版路线。

### 发布级规格

公开 Demo 不等于 v0.14 作品集 / GDD 基线。进入公开 Demo 前必须满足：

- **开发入口**：所有跳关、加资源、全部解锁入口默认不可见；公开构建中建议完全禁用。
- **教程**：首次开始前仍可提示，但不能阻断玩家；教程内所有规则必须与当前实现一致。
- **文字与 UI**：1280x720、16:9 大屏、常见中文系统字体下无按钮遮挡、长文本溢出或确认框不可点。
- **存档**：旧存档缺字段可补默认值；坏存档降级为警告；返回主菜单不丢已获得图鉴、碎片和结局收藏。
- **资产**：所有主菜单、章节背景、角色、敌人、Boss、设施、卡面框、终局背景必须有发布级或明确可接受的统一风格资产。
- **音频**：程序合成音频可保留为 Demo 风格，但 GDD 必须列出 BGM 主题、SFX 事件和音量默认值；若替换外部音频，需补授权来源。
- **导出**：Windows 包必须能双击启动；导出后跑一次新手教程、开始冒险、返回主菜单、打开设置、退出游戏的人工验收。

### 2026-05-03：v0.6.1 启动闪退修复记录

问题现象：

- 项目启动后立即退出。
- Godot headless 普通启动报错：`res://scenes/main_menu.tscn:1 - Parse Error: Expected '['`。

原因：

- 使用 Windows PowerShell `Set-Content -Encoding utf8` 更新版本号时，`scenes/main_menu.tscn` 被写入 UTF-8 BOM。
- Godot `.tscn` 文本资源解析器在该文件第 1 行遇到 BOM 后，没有识别到期望的 `[`，导致主场景加载失败。

修复：

- 将 `project.godot`、`scenes/main_menu.tscn`、`export_presets.cfg`、`README.md`、`CHANGELOG.md` 统一重写为 UTF-8 无 BOM。
- 普通启动路径验证通过。
- v0.6.1 正式回归脚本验证通过，输出 `[v0.6 regression] PASS`。

后续规范：

- 修改 Godot `.tscn`、`.tres`、`.gd`、`.godot`、`.cfg`、`.json` 等文本资源时，不使用 PowerShell `Set-Content -Encoding utf8` 直接覆盖文件。
- 如需脚本批量写入，必须使用 `.NET UTF8Encoding(false)` 或其他明确的 UTF-8 无 BOM 写法。

### 2026-05-08：v0.10 三流派关键词构筑深化

版本定位：

- v0.10 不新增敌人机制，不重做 Boss；本轮只深化玩家卡牌构筑身份。
- 目标不是整体增强玩家，而是让山经、海经、荒经的路线选择更清晰。

已完成内容：

- 卡牌模型新增 `keywords: Array[String]`，数据库读取旧数据时默认空数组。
- 六个关键词锁定：山经 `根脉 / 生息`，海经 `潮涌 / 湿润`，荒经 `凶势 / 血祭`。
- 92 张卡全部保留关键词字段，其中 v0.10 的 74 张完成关键词重写，v0.11 新增 18 张角色卡直接按关键词规范写入；通用卡不进入三流派关键词体系。
- 卡牌 UI 增加短关键词标签，避免遮挡费用、流派、类型和稀有度。
- 图鉴详情页增加关键词规则说明，并用颜色区分关键词和稀有度。
- `血祭` 自伤统一走玩家受击路径，先扣护盾，再扣 HP。
- 图鉴有效计数改为只统计真实 `card.*` / `beast.*` 条目；旧存档或 smoke 写入的无效 key 会在读取/保存路径被过滤，避免出现超过总数的异常显示。
- 地图默认移动速度降至更可控的步行速度，按住 `Shift` 可加速，赶路速度接近旧版本。
- 新增 `tools/v10_keyword_smoke.gd`，覆盖关键词合法性、关键词效果承载、卡面标签、图鉴说明、有效图鉴计数和血祭护盾规则。
- 扩展 v0.8/v0.9 smoke：v0.8 增加移动速度检查；v0.9 使用真实图鉴条目，不再写入 fake codex key。

设计结论：

- 关键词必须是构筑路线标签，不是单纯卡面装饰；`潮涌` 必须对应抽牌/灵韵流动，`湿润` 必须对应湿润状态或湿润触发，`血祭` 必须有真实代价。
- 图鉴进度属于长期存档数据，所有 UI 必须使用同一“有效条目”口径，不能直接展示存档字典长度。
- 卡面只显示短关键词，完整规则说明放在图鉴；这样能保持战斗界面可读性，同时给图鉴保留学习价值。
- 地图移动默认速度应服务探索观察，快速赶路交给 `Shift`，避免玩家在节点和碰撞边缘过冲。

### 2026-05-09：v0.12 终局闭环

#### 本次目标

- 五章净化后不再直接回祖父书房，而是进入独立终局场景「忘川之心」。
- 用轻量对话系统完成三档结局判定，把图鉴学习、事件选择和长期收藏连成闭环。
- 本轮不扩内容规模，不新增终局 Boss，不重构普通事件 UI。

#### 已实现

- 新增 `scenes/finale/finale.tscn` 与 `scripts/finale/finale_view.gd`，视觉基调为“古卷黑水”：暗水、残卷和金色字迹。
- 第五章最终 Boss 清完后进入忘川之心；终局结束后回到祖父书房。
- 事件选项新增 `ending_marker` 字段，固定为 `guard / companion / practical`，全量覆盖 40 个事件的选项。
- `RunState` 新增本局伏笔计数，支持 reset、record、合法性检查和标签显示；新局重置，不写入长期存档。
- `GameState` 新增三档结局定义、结局判定、已见结局和最高结局保存。
- 祖父书房新增终局收藏展示。
- 图鉴新增学习闭环：打开已解锁条目会写入已研读状态，复盘页列出未研读条目，终局条件页解释当前图鉴比例与守护/陪伴阈值。
- 忘川之心判定页新增条件解释，例如图鉴已达标但守护/陪伴不足时，会明确提示距离「山海重明」还缺多少伏笔。
- 新增 `tools/v12_finale_smoke.gd`，覆盖事件标记合法性、伏笔计数、三档阈值、结局保存兼容和「第五章 -> 忘川之心 -> 祖父书房」路由。
- 修复 headless smoke runner 超时问题，并切断 `GameState` / `RunState` 编译期互相引用。

#### 设计结论

- 真结局不依赖随机刷到少数关键事件，而是依赖所有事件选项共同提供的伏笔倾向。
- `守护 + 陪伴` 被视为“愿意理解”的有效证据；`实用` 可以提供即时收益，但不推动真结局。
- 图鉴“完成度”影响结局，“已研读”服务学习复盘；两者分开，避免玩家为了结局被迫反复点开条目。
- 结局收藏只保存轻量结果，不保存完整对话流水或每次通关历史，为后续成就 / 残卷系统预留空间。
